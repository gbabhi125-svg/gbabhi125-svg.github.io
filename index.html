CASE 001

AASE — Agent Autopsy & Self-Evolution Engine

Python · FastAPI · ChromaDB · Groq / Gemini · distributed, two-node · 2026
18.3%→7.1%failure rate, repaired
›

A five-agent system that wraps any LLM agent: a deterministic validator catches a failure, three specialised agents argue its root cause through adversarial debate, and a fourth rewrites the failing agent's own system prompt. Integrated in one line, with no retraining.

01

Designed a seven-category failure taxonomy and generated a 1,050-trace labelled benchmark from 10,612 real tasks; reached 70/70 on the controlled set and evaluated against 184 human-annotated traces from the Who&When benchmark (ICML 2025) — reporting the real-world range across five runs rather than one favourable number.

02

Ran a self-evolution study over two independent task sequences with a regression gate that rejects any repair breaking a previously-passing task — the result in the panel above.

03

Showed a repair derived from one failure generalised to four unseen tasks of the same failure mode (2/6 → 6/6) while breaking none of six control tasks — a collateral-damage comparison the prior literature does not report.

04

Diagnosed a silent production defect: 323 stored repairs had been written by one embedding model and queried by another. Rebuilt the vector store, moving self-match distance from 1.01 to 0.00 against 1.54 for unrelated text.

05

Distributed the architecture across two machines over HTTP — two agents per host, arguing across the network — and shipped a live operator console with four input modes over 1,234 indexed traces, full run history with replay, and an operator-override mode to isolate whether the diagnosis or merely the edit produced the fix.

CASE 002

AgroSentinel India — Agricultural Risk Intelligence

Python · Flask · React · scikit-learn · XGBoost · SHAP · Docker · 2026
R² 0.97yield prediction
›

A production risk platform for Indian farmers, built on three raw government datasets consolidated into a single modelling table.

01

Consolidated IMD rainfall (1901–2015), the Agricultural Census and PMFBY into 236,449 records across 105 crops and 33 states, resolving inconsistent naming and missing-rainfall gaps.

02

Benchmarked six algorithms across four targets — yield, drought risk, crop-failure probability, planting season — auto-selecting the strongest per task; Random Forest reached R² = 0.97 on yield and 99.8% on drought classification under 5-fold cross-validation.

03

Shipped a 12-endpoint Flask API blending offline models with two live sources (Agmarknet mandi prices, Open-Meteo), so predictions reflect current conditions, not historical averages.

04

Built the React dashboard end to end: SHAP explanations so a farmer sees why a recommendation was made, six-language localisation, PDF export, and in-app model retraining without redeployment.

CASE 003

Vigilance AI — Identity Blast-Radius Engine

Python · Flask · scikit-learn · D3.js · Société Générale Hackathon · 2026
600identities scored
›

Identity sprawl and privilege-abuse detection across five enterprise systems, built under hackathon time pressure.

01

Built a risk-scoring engine over 600 identities across Active Directory, AWS IAM, Okta, Salesforce and GCP, flagging stale, orphaned, over-privileged and role-changed accounts with a per-factor score breakdown.

02

Paired every finding with an automated remediation playbook and a breach-impact simulator estimating blast radius and lateral-movement paths from a compromised identity.

03

Delivered beyond the base requirement: a D3.js force-directed privilege graph, K-means behavioural clustering, anomaly heatmaps, five Separation-of-Duties checks, and compliance mapping to NIST AC-2, GDPR Art. 32 and ISO 27001 A.9.
